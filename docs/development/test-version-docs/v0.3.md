# melorx v0.3 — Manual Testing Guide

This guide verifies every capability added in v0.3 on top of the v0.1 foundation. It is scoped to the *new* surface area — run the full v0.1 guide first to establish the baseline (Docker, migrations, ONCHigh seed, RxNorm enrichment).

What's new in v0.3:

- Community contribution pipeline (`pipeline/sources/community/`*) with CI validator and PR template
- `@melorx/client` npm package — typed HTTP client (published under `next` tag as `0.3.0-rc.1`)
- OpenFDA NLP extractor: bulk download, SHA-256 verification, pattern-based extraction, confidence scoring (ADR-004)
- `drug_interaction_review` queue + `pipeline_state` table (migration `0001`)
- `promote` job: moves eligible review rows into `drug_interaction` (Rule #6 enforced)
- `@melorx/cli` workspace with `review`, `promote`, `ingest partition`, `ingest all` subcommands
- API read-gate verification: 6 integration tests prove `confidence < 0.75` rows are never served

---

## Prerequisites

- The v0.1 guide has been completed through step 4c (curated seed + class rules + RxNorm enrichment).
- `DATABASE_URL` in `.env` points at a running Postgres container.
- Node.js 22+, pnpm 9+ installed.
- Network access to `https://api.fda.gov` (for step 6 only).

If you are starting from a clean clone:

```bash
pnpm install
docker compose up -d
pnpm db:migrate
pnpm db:seed
pnpm db:seed:classes   # requires RxNorm RRF files at pipeline/resolver/raw/
pnpm db:enrich
```

## 6. `promote` command — Rule #6 enforcement

### 6.1 Promote the approved synthetic row from 5.5

```bash
pnpm db:promote
```

Expected:

```
promote: eligible=1 promoted=1 blocked_missing_concept=0 blocked_existing_pair=0
```

Verify the row now exists in `drug_interaction` with confidence preserved:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "SELECT drug1_rxcui, drug2_rxcui, severity, confidence FROM drug_interaction WHERE confidence = 0.85;"
```

Expected: 1 row — `5640 | 29046 | moderate | 0.85`.

Verify the review row is now marked approved with `promoted_interaction_id` set:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "SELECT status, promoted_interaction_id IS NOT NULL AS linked FROM drug_interaction_review WHERE drug1_rxcui='5640' AND drug2_rxcui='29046';"
```

Expected:

```
  status  | linked
----------+--------
 approved | t
```

### 6.2 Sub-threshold rows are never promoted

Insert a 0.60-confidence pending row:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx -c "
INSERT INTO drug_interaction_review
  (drug1_rxcui, drug2_rxcui, severity, mechanism, sources,
   confidence, pattern_id, source_sentence, status)
VALUES
  ('36567', '703', 'moderate', 'fixture',
   ARRAY['{\"name\":\"x\",\"url\":\"https://x.test/3\",\"type\":\"fda_label\",\"accessed_date\":\"2026-04-22\"}']::jsonb[],
   0.60, 'TEST_LOWCONF_V1', 'low-confidence test sentence.', 'pending');"

pnpm db:promote
```

Expected:

```
promote: eligible=0 promoted=0 blocked_missing_concept=0 blocked_existing_pair=0
```

The sub-threshold row stays pending — confirm:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "SELECT confidence, status FROM drug_interaction_review WHERE pattern_id='TEST_LOWCONF_V1';"
```

Expected: `0.60 | pending`.

### 6.3 Rule #6 read-gate: API never serves the 0.85 synthetic pair

Start the API:

```bash
pnpm dev &
sleep 3
```

Query the promoted synthetic pair (severity moderate, confidence 0.85) — it should be served:

```bash
curl -s "http://localhost:3000/v1/interactions?drug1=5640&drug2=29046" \
  | jq '.data.interactions[] | select(.confidence == 0.85)'
```

Expected: 1 object with `"severity": "moderate"`, `"confidence": 0.85`.

Now flip the pair's confidence to 0.74 (just below threshold) and re-query:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "UPDATE drug_interaction SET confidence = 0.74 WHERE drug1_rxcui='5640' AND drug2_rxcui='29046' AND confidence = 0.85;"

curl -s "http://localhost:3000/v1/interactions?drug1=5640&drug2=29046" \
  | jq '.data.interactions[] | select(.confidence == 0.74)'
```

Expected: empty output — the row is filtered by the read gate.

Restore confidence to 0.85 so the rest of the guide works:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "UPDATE drug_interaction SET confidence = 0.85 WHERE drug1_rxcui='5640' AND drug2_rxcui='29046' AND confidence = 0.74;"
```

### 6.4 Promote detects sub-threshold leakage

The promote command exits with code 2 if any `drug_interaction` row has `confidence < 0.75`. Force a violation:

pnpm db:promote

```

Expected:

```

...

Restore:

## 7. OpenFDA bulk download + extractor

### 7.1 Dry-run: enumerate partitions without downloading

```bash
pnpm cli ingest all --dry-run --max-partitions 2
```

Expected (exact partition count varies with each OpenFDA publish):

```
OpenFDA index: <N> drug label partition(s) listed
[dry-run] would download drug-label-0001-of-<N>.json.zip (? MB)
[dry-run] would download drug-label-0002-of-<N>.json.zip (? MB)
ingest all: listed=<N> downloaded=0 skipped=0 failed=0 inserted=0
```

This verifies:

- `https://api.fda.gov/download.json` is reachable
- The index parser handles the real response shape
- The skip-if-unchanged logic is bypassed correctly by `--dry-run`

### 7.2 Ingest a single real partition

This downloads ~30 MB and extracts candidate pairs into the review queue. Expect 30–90 seconds.

```bash
pnpm cli ingest all --max-partitions 1
```

Expected log shape:

```
OpenFDA index: <N> drug label partition(s) listed
OpenFDA partition ingested: labels=<L> skipped=<K> candidates=<C> inserted=<I> deduped=<D> class_refs=<X> unresolved=<U>
ingest all: listed=<N> downloaded=1 skipped=0 failed=0 inserted=<I>
```

Typical numbers: ~3000 labels, hundreds of class references (filtered), many unresolved (surface forms not in `drug_concept`), a handful of candidates inserted into review.

If upstream publishes a checksum and it mismatches, the CLI throws with `partition <id> checksum mismatch: expected=<hex> actual=<hex>`. If upstream omits a checksum, a WARN is logged and the actual computed hash is stored in `pipeline_state`.

Verify `pipeline_state` recorded the run:

```bash
docker exec $(docker compose ps -q postgres) psql -U melo -d melorx \
  -c "SELECT source_name, partition_id, records_processed, last_ingested_at FROM pipeline_state ORDER BY last_ingested_at DESC LIMIT 5;"
```

Expected: 1 row with `source_name = openfda:drug-label`, partition_id matching the partition filename, and a sane `records_processed` count.

### 7.3 Re-run — skip unchanged partitions

```bash
pnpm cli ingest all --max-partitions 1
```

Expected:

```
ingest all: listed=<N> downloaded=0 skipped=1 failed=0 inserted=0
```

The partition is unchanged (same checksum), so it is skipped.

### 7.4 Force re-ingest

```bash
pnpm cli ingest all --max-partitions 1 --force
```

Expected: `downloaded=1 skipped=0`. Dedup means `inserted=0` (all extracted candidates already exist in the review queue):

```
ingest all: listed=<N> downloaded=1 skipped=0 failed=0 inserted=0
```

### 7.5 Inspect extracted review rows

```bash
pnpm review list --limit 10
```

Expected: up to 10 pending review rows with `confidence >= 0.00`, ordered by confidence DESC. Each row shows the subject+object RxCUIs, matching pattern id, and the originating label sentence.
